# План доклада: «Кинетический манифест»

**Целевая аудитория:** Frontend-разработчики и архитекторы любого стека (React/Vue/Angular/Solid, любой стейт-менеджер)
**Длительность:** 35–40 минут · **Событие:** MoscowJS #71
**Формат:** Концептуальный доклад с архитектурными инсайтами; Effector — рабочий пример реализации

**Главный тезис доклада:**
> Управление состоянием — это не выбор библиотеки, а выбор **мировоззрения**. Данные в современном вебе не лежат статично — они **движутся** через граф правил. «Кинетический» подход (event-driven + декларативность + реактивность) — это паттерн, а не фреймворк. Effector, RxJS, XState — лишь разные способы его реализовать.

**Что слушатель уносит:**
1. Понимание кинетического подхода как **способа мышления** (события вместо команд, связи вместо порядка).
2. Карту реализаций: что общего у Effector / RxJS / signals / стейт-машин и чем они различаются.
3. **Честный** ответ на вопрос «когда это стоит внедрять, а когда — overkill».

**Принцип построения:** подход — герой, библиотеки — иллюстрации. Ни один вывод доклада не должен зависеть от конкретного фреймворка. Код показываем на Effector (как на знакомом примере), но мысль — стек-независимая.

**Драматургия (problem-first):** боль — раньше лекарства. Сначала зал чувствует, почему императив не масштабируется, и только потом получает декларативный ответ. Выигрыши (Часть 3) читаются как payoff обещанной проблемы.

## Часть 1. Что такое кинетический подход (концепт, без кода) (10–12 мин)

### Слайд 8: Что такое «кинетика»? (термин)
- Этимология *kinētikos*; трио механики: статика / кинематика / динамика. Честно: строгого раздела «кинетика» в рус. школе нет.
- Где живёт: физическая, химическая, англ. *kinetics*. 🔑 Про скорость и эволюцию процессов во времени.

### Слайд 9: Кинетика как метафора
- «Кинетика» = имя из KRL + метафора. Маппинг: импульс→event, траектория→граф, трение→debounce, препятствие→filter, результат→effect.
- Лейтмотив: строишь русло, а не толкаешь воду.

### Слайд 10: KRL — язык для «Живого Веба»
- Фил Виндли, Kynetx (2007–2008), KRE. Идея «personal cloud»; три кита: entity orientation / event binding / persistent values. Salience.

### Слайд 11: ECA — сердце KRL
- Event–Condition–Action + пример (подсветка `js`). Метафора ружья. Мост: тот же ECA под Effector/reducer'ами/стейт-машинами.

### Слайд 12: Три столпа подхода
- Event-driven (уведомление, не команда) + Declarative (связи, не порядок) + Reactivity (граф сам в один тик). Свойства подхода, не библиотеки.

### Слайд 13: Реактивность — не изобретение фронтенда
- Таймлайн Excel(1979) → … → Effector → Signals. Меняется лишь, насколько явно виден граф.

## Часть 3. Чем подход реально выигрывает (6–7 мин)

### Слайд 17: Выигрыш 1 — смерть race conditions
- 🔁 **Callback к слайду 6**: та самая гонка из `SearchUsers` — вот как лечится. `sample` берёт source в один тик.
- То же в RxJS (`withLatestFrom`) — свойство подхода.

### Слайд 18: Выигрыш 2 — логика отделена от UI
- UI генерирует события; модель живёт без React/Vue. Тест без рендера, перенос между фреймворками, тонкий компонент.

### Слайд 19: Выигрыш 3 — изоляция для SSR и тестов
- `fork()` + `allSettled()` — скоуп на запрос/тест, нет утечки состояния между пользователями.

## Часть 4. Trade-offs: когда стоит и когда НЕ стоит (6–8 мин) ⭐

Самая честная часть. Без неё доклад — реклама.

### Слайд 20: Когда кинетический подход окупается
- Много асинхронности/гонок, real-time/потоки, сложные зависимости, тестируемость логики, большая команда/долгий проект.

### Слайд 21: Когда это overkill
- Маленькое приложение/локальный стейт, прототип/MVP, серверное состояние (TanStack Query), неготовая команда.
- Тезис: инвестиция в сложность данных. Нет сложности — нет окупаемости.

### Слайд 22: Цена, о которой молчат
- Дебаг графа; spooky action at a distance; выбор яда (бойлерплейт vs неявность); потеря линейной читаемости.

### Слайд 23: Как внедрять, не ломая всё
- Точечно → слой поверх (saga/observable) → сначала разделить UI и логику.

## Заключение (4–5 мин)

### Слайд 24: Главные тезисы (стек-независимые)
1. Состояние **движется**, а не лежит. 2. Три столпа. 3. Паттерн, а не библиотека (ECA из KRL).
4. Реализации различаются тем, **что делают явным**. 5. Выигрыши: race, логика ≠ UI, тесты/SSR. 6. Trade-off честно.

### Слайд 25: Что сделать в понедельник (без смены стека)
- Думай событиями; выноси логику из компонента; описывай связи; спрашивай — есть ли у меня та сложность. Ни один пункт не требует менять стек.

### Слайд 26: Помните вопрос в начале? (callback)
- Возврат к опросу про событийный веб. Раз согласились — странно вести состояние командами. Кинетика = следствие этого «да».

### Слайд 27: Финальная мысль (цитата)
- «Строишь русло, а не толкаешь воду… Effector — лишь то, из чего сделано русло.»
